# 个人项目选题报告

## 选题

**健康陪聊助手（C 端）**：用户用自然语言问部位、疾病、症状、检查、指标和生活注意事项，系统按细意图走图谱或手册检索，再组织回复。不替代就诊。

仓库（本作业提交地址）：https://github.com/cuiyucheng996/homework.git  
业务代码另在课程项目 `uvgraph` 的 `B 端 / C 端` 目录迭代。

## 为什么选这个题

课堂电商客服把「细意图 → 抽实体 → 图谱 Cypher」跑通。个人项目把同一套骨架换到健康场景：

| 课堂电商 | 个人项目（健康陪聊） |
|---|---|
| 查询某商品的所有单品 | 查询某疾病常见有哪些症状 / 某部位有哪些病 |
| SPU / SKU | 部位 / 疾病 / 症状节点 |
| UIE 抽「商品」 | 抽疾病、症状、部位并做同义对齐 |
| Belong 关系到单品 | Neo4j 问诊关系；检查类走手册检索 |

选题能复用课堂的意图分类、槽位、图谱查询，同时覆盖陪聊里的指代补全、风险拦截（急救/剂量）等额外环节。

## 要做的范围

1. 七个大类意图，公共知识下再拆细意图（部位病、病症、检查含义、指标范围、症状注意事项等）。
2. 细意图绑定工具：图谱 `query_consult_graph` 或手册 `search_exam_handbook`，不混用。
3. 多轮：指代补全后再检索。
4. 评测台核对：抽出实体、对齐结果、是否查了向量库。

## 不做的范围

不开药、不定剂量、不把急症问答当成普通闲聊；不提交课堂 BERT/UIE 大模型权重。

## 与本次作业的关系

本次作业按课堂要求实现 **查询某商品的所有单品** 的单轮聊天（意图、纠错、抽商品、查 SKU），证明图谱客服主路径可运行。健康陪聊是同一路径在医疗知识图谱上的选题落地。
